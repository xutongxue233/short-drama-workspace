# 映序 · 使用指南

[English overview](../README.md) · [简体中文主页](../README.zh-CN.md)

一个以项目群聊为中心的本地创作工作台。导入小说章节，由总制片组织编剧、内容审核、角色设计、分镜导演、视频制作和剪辑 Agent 接力工作；关键决定由创作者确认。

## 运行

需要 **Node.js 22.13 或更新版本**（本项目使用 Node 自带的 `node:sqlite`，当前可能输出实验性提示）。

```powershell
git clone https://github.com/xutongxue233/short-drama-workspace.git
cd short-drama-workspace
npm ci
npm run workbench
```

打开 <http://127.0.0.1:5173>。前端由 Vite 提供，API 监听 `127.0.0.1:3001`。

`workbench` 的 API 不自动重载，适合持续运行真实模型任务；前端仍支持热更新。需要边改后端边调试时使用 `npm run dev`，但文件重载会中断正在执行的节点。两种启动方式使用相同端口，不要同时运行。

单进程运行构建产物：

```powershell
npm run build
npm start
```

打开 <http://127.0.0.1:3001>。关闭运行终端会停止服务；下次启动继续读取本机项目。数据库位于 `data/workbench.sqlite`，不要只复制正在写入的主文件；备份前先停止服务并复制整个 `data` 目录。

可将 `.env.example` 复制为 `.env` 后修改配置。`npm run workbench`、`npm run dev` 和 `npm start` 自动加载 `.env`，进程环境变量优先。`API_PORT` 改变后端端口，`WEB_PORT` 改变开发页面端口；`WORKBENCH_DATA_DIR` 指定数据库目录，相对路径始终从项目根目录解析。Vite 代理会同步使用 `API_PORT`。统一配置放在 `.env`，不要把服务端配置分散到 Vite 专用的 `.env.local` 或 `.env.development`。

## 账号与群聊协作

首次打开工作台先创建管理员。管理员在右上角「账户与安全 → 团队账户」创建真人或 Bot 账号；没有开放注册。其他成员使用分配的账号登录后，可在「我的账户」修改密码和退出。管理员可停用账号、重置密码和查看安全记录；这些权限不代表能访问未加入的项目。

项目所有者在「群成员」输入已有账号的用户名，选择「可编辑」「可讨论」或「只读」。可编辑成员能修改内容和调用 Agent，可讨论成员能发群消息，只读成员只能查看。所有者可以修改权限或移除成员，移除后接口会立即拒绝后续访问。

账号身份、项目权限与分工分别展示。例如真人「林剪辑」可填写分工「剪辑师」，也可以只有「用户」身份和「可讨论」权限；AI 剪辑 Agent 仍单独标记为 Agent。Bot 使用自己的账号发言，不会冒充真人。新消息和人工审批记录按实际登录账号署名，只有本人看到「我」，旧版没有账号信息的消息显示「历史用户」。

群聊默认发送普通消息，所有项目成员可见。提及真人或 Bot 不会触发模型请求；需要 AI 回复时选择 Agent 或相应协作模式，且需要可编辑权限。退出或账号失效后，页面清除该账号的工作台内容与草稿。

共享给其他电脑时，使用构建产物、HTTPS 反向代理和 `.env.example` 中的 `WORKBENCH_ORIGIN` 等设置。详细部署、首次初始化令牌和备份要求见 [安全说明](../SECURITY.md)。

## 从本集原文开始制作

1. 新建项目，填写名称、题材与初步风格，无需确定全剧集数。创建后导入本集要改编的小说章节或片段，可粘贴文字或导入 UTF-8 TXT、Markdown 文件。
2. 在「模型接入」配置服务并在「Agent 中心」绑定，点击「开始 / 继续制作」。总制片根据已提供原文确定本集范围，确认风格、本集时长、画幅和平台后，每轮创作一集。
3. 在确认卡中批准，或填写修改意见。系统会保存反馈并重新执行对应节点。
4. 在「项目资产」查看设定与成果，锁定角色标准；在「制作流程」查看节点产物及重新制作入口。
5. 在「项目记忆」添加固定事实、查看已确认决策、整理阶段摘要。
6. 右侧「项目概况」显示已建剧集、归档与共享资产；「本集制作」单独显示节点状态、当前负责人和下一位接手成员。点击群成员、节点或「全部工作记录」，按成员、节点、事件类型查看执行、确认、返修、交接和失败详情。
7. 完成本集全部节点验收后，在「剧集档案」中归档并开始下一集。新集单独导入原文、重新确认制作方案，沿用已锁定角色和场景。历集原文、节点产物和工作记录以只读快照保留；归档表示流程验收，不代表完整成片已生成。
8. 导出项目 JSON，包含当前集与剧集档案、原著、对话、工作流、资产引用和记忆；不包含模型密钥。

所有创作使用已配置的模型。没有演示模式或自动模板回执，缺少服务或绑定时会显示具体缺口。首次启动不创建示例项目；不要求整本小说，也不会把原文章数换算成总集数。

升级已有工作台时，真实单集项目的审批、锁定资产和进度会保留。旧模板产物保留为历史资料，相关项目回到原著拆解；旧多集制作方案需要重新确认本集范围。迁移前的完整工作区快照保存在本地 SQLite 的 `migration_backups` 表，仅作本机恢复，不通过状态接口或项目导出暴露。原文、历史消息和下载素材均保留。

## 当前具备的能力

- **多个项目群聊**：原文、消息、工作流、审批、资产、记忆相互隔离。
- **项目内逐集创作**：不预设总集数；每集单独管理原文、审批和制作节点，项目角色、场景与素材持续复用。当前集验收后才能开启下一集，历史剧集只读，暂不支持多集同时制作或重新打开归档集。
- **成员工作日志**：按成员、节点、事件筛选，区分请求确认、批准、返修和实际交接；展开查看完整产物、人工反馈和原始错误。新执行保存事件关联；旧记录仅在有明确证据时整理交接，并标注来源。历史记录缺失的耗时、模型及请求数据不会推测补造。
- **群成员**：统一展示姓名与岗位，仅 Agent 显示身份标签，可从成员直接查看工作记录。当前本地工作台的用户为「我」，成员数包含本人；邀请入口展示尚未入群的 Agent。
- **可恢复的制作流程**：原著拆解 → 剧本改编 → 合规校对 → 角色定妆 → 分镜设计 → 视频制作 → 剪辑交付；支持中止、失败重试与从指定节点重做。
- **人工决策**：风格、剧本、角色、分镜、交付分别请求确认；过期审批无法重复提交。
- **Agent 中心**：7 个默认角色，可修改职责、系统提示词、模型绑定和启用状态。
- **模型中心**：12 个常用模型接入预设，多个文字 / 图片 / 视频接口独立管理，支持获取模型列表、搜索选择、连接检查、密钥替换或清除。
- **一致性约束**：已确认角色和分镜会携带 ID、版本、描述和参考媒体进入后续请求。修改上游会要求下游重新制作。
- **资产与记忆**：资产库按所选项目分页展示；项目内保存固定事实、已确认决策和阶段摘要。群聊先加载本集最近 50 条消息，可继续查看更早记录；完整原文和聊天仍保留。
- **本地素材库**：每次真实生成的图片、视频独立留档，返修不覆盖旧素材；自动下载到数据目录的 `media` 子目录，按所选项目分页查询，支持媒体类型、保存状态和关键词筛选，以及预览、下载和重试保存。
- **本机持久化**：SQLite 按项目和实体拆表，在事务中保存变化记录；旧数据库自动迁移并保留原始快照，服务重启不会把中断节点误报为完成。
- **自适应界面**：桌面三栏工作台，小屏保留项目切换、新建及各管理页面。

预设信息核对日期：2026-10-12，MiniMax 预设于 2026-10-13 新增。模型 ID 和接口地址均可修改，以服务商控制台的可用模型与地域为准。预设本身不创建远端账户、不购买额度、不调用模型，也不覆盖已保存的服务配置。

MiniMax 预设提供图片 `image-01` / `image-01-live` 和视频 `MiniMax-H3` / `MiniMax-H3-Max`，默认国内站 `https://api.minimax.cn`，国际站使用 `https://api.minimax.io`。图片最多 1500 字符，仅支持单人物参考；角色节点使用精简布局提示词，保留完整基础外观，超限明确报错。H3 系列使用 v2 视频接口，支持画幅与最多 9 张图片参考；H3 时长 4–15 秒，H3 Max 5–15 秒。不支持的参数或参考不会静默丢弃。旧 Hailuo 型号虽支持 v1 接口，但无法接收显式画幅，短剧节点优先使用 H3。接口见[图片文档](https://platform.minimax.cn/docs/api-reference/image-generation-i2i)、[视频文档](https://platform.minimax.cn/docs/api-reference/video-generation-v2-create)。

模型服务编辑和 Agent 配置均有「获取模型」。OpenAI 兼容、Anthropic、MiniMax 通过服务端只读查询列表；未提供模型列表的接口保留官方预设与手动输入。界面区分远程结果和预设，列表可见不代表账号具备生成权限。查询草稿不会保存服务，修改地址或协议后必须重新输入密钥才能查询，避免把已保存密钥发送到其他地址。切换 Agent 服务会清空旧模型覆盖值，默认沿用新服务型号。

模型名称以实际供应商提供的名称为准。接口兼容不代表所有品牌都已独立测试。显式绑定的接口失效时会报错，不会悄悄换成其他计费服务。

文字节点需要文字服务。角色设计先生成文字设定，再调用配置的图片服务；视频节点可使用 Seedance、MiniMax 原生接口或视频 Webhook。Seedream / Seedance 会携带参考图片及资产文字约束；当前 Seedream 5.0 pro / flash 预设最多 10 张参考图，Seedance 2.5 预设最多 30 张。未知型号或专用 `ep-` 接入点带参考图时会明确拒绝，不会丢弃角色约束。当前原生媒体适配只传图片参考，音视频参考需自行适配 Webhook。

角色库可以从空白开始，每次只需导入本集小说片段，无需提供完整小说。角色规划优先读取当前已批准剧本，按本集实际出场需要创建设定；后续导入章节时保留已锁定角色，逐步补充新人物。未命名人物沿用其称谓，已批准的改编新增人物单独标明来源；有证据的“称谓（姓名）”归一到同一角色。“家人”等群体需要拆成有出场依据的独立人物，不能共用一张混合人物形象。规划校验失败时自动反馈原因并纠正一次，通过校验后才请求图片。未明确的外貌作为设计提案审核，确认后才成为后续分镜与视频的视觉标准。

新版角色设计把固定的年龄、五官、发型、服装与配色存为 `characterDesign.baseAppearance`，把逆光、现形、异常妆效等另存为 `sceneStates`。项目可通过 PATCH `visualStyleGuide` 细化统一画风；改变该标准只使角色及后续节点失效，保留已批准剧本与合规结果。新结构化生图按「一位角色样板 → 人工确认画风与基础造型 → 批量生成其余角色 → 完整角色图最终确认」推进。样板确认不会直接锁定角色或进入分镜；本轮所需角色图必须齐全且在确认卡成功加载，人工核对五官、完整身体、固定服装与统一画风后，才最终锁定并进入分镜。失败重试复用本轮成功图片，符合当前标准的已锁定角色可继续复用。当前每位角色只生成一张基础图，三视图、面部特写、表情和状态变体尚未自动编排，也不承诺模型输出或后续视频必然一致。

分镜以逐镜表提交审核，明确镜号、起止秒数、单镜时长、画面、出镜人物及锁定资产 ID / 版本、声音、运镜与制作方式。仅画外音人物必须注明不出镜，纯黑字卡等镜头明确标为「后期制作」。视频节点从已批准分镜中选取首个非后期镜头，使用该镜实际时长、已确认画幅及对应参考图请求所选模型；模型能力以具体接入和型号为准，没有适用于全部视频模型的固定时长范围。交付节点依据实际媒体台账列出已生成镜头、请求参数与保存状态，并列明待补镜头及后期任务；首个镜头素材不代表整集成片，请求时长也不代表已实测的媒体时长。

OpenAI 兼容图片接入在无参考图时使用 `POST /images/generations`，带参考图时使用 `POST /images/edits`，按 [OpenAI 图片编辑 API](https://developers.openai.com/api/reference/resources/images/methods/edit) 的 JSON `images[].image_url` 字段传入图片（最多 16 张）。角色名称、版本和约束与图片编号对应，图片内容不会混入文字提示词。网关需支持该编辑接口；不支持时明确报错，不会丢弃参考图降级生成。生图提示词与资产说明合计超过 32,000 字符时提示精简，不会自动截断。参考资产有助于视觉一致性，仍需要逐次审核生成成果。

连接测试只执行 GET：OpenAI 兼容 / Anthropic 使用 `/models`，方舟使用只读视频任务列表接口，Webhook 使用约定的健康检查。不会提交生成请求；方舟任务列表检查不验证图片服务或指定模型的生成权限，列表检查通过也不等于一定能生成。

API 密钥只保存在服务端，使用 AES-256-GCM 加密，状态接口仅向管理员返回 `hasKey`。编辑时密钥留空表示保留原值；「清除已保存密钥」会删除它。备份需同时保留数据库旁的 `.key` 文件；项目文字和媒体本身未加密。首次启动创建管理员，再通过账号管理创建真人或 Bot 账号。项目负责人可按账号名邀请成员，单独设置项目权限及可选分工；普通用户不需要绑定专业角色。完整权限和远程配置见 [安全说明](../SECURITY.md)。

### 素材保存与备份

「资产库」管理剧本、角色标准和分镜等创作版本；「素材库」保留每次生成的媒体，包括待确认、返修前及模型测试产物。生成成功后先登记素材，再下载本地文件；下载失败仍保留生成记录和可用的原链接，可在素材库重试，不必重新付费生成。历史上已经失效且未保存的链接无法恢复原文件。

默认目录是 `data/media`；设置 `WORKBENCH_DATA_DIR` 后随数据目录移动。图片最多 30 MiB、视频最多 300 MiB、音频最多 100 MiB；超过限制、返回错误网页或网络超时会明确标记保存失败。已有远程资产可通过项目素材库的补存入口下载。已保存图片作为云端模型参考时读取本地内容，不向供应商发送无法访问的本地路径。

导出的项目 JSON 包含素材索引，不内嵌媒体。完整备份请停止工作台后复制整个数据目录（数据库和 `media`），不要只复制 JSON 或 SQLite 主文件。

开发调试可显式调用 `POST /api/providers/:id/image-test`，正文包含 `projectId`、精确 `model` 和可选 `prompt`。该操作会实际生成一张图片并归入所选项目素材库，可能产生供应商费用；不会修改模型配置、Agent 绑定或项目审批。它与仅执行 GET 的连接检查不同。

### 数据库与项目加载

工作台继续使用本机 SQLite，无需配置额外数据库服务。当前 schema 为 v1：项目、消息、资产、素材、原文、节点、剧集、Agent 和模型配置分别存储，项目子记录通过 `project_id` 关联；每条实体的详细字段仍保存为 JSON。保存时在同一事务中写入新增、修改和删除的记录，不再重写一份完整工作区 JSON。

旧数据库首次由新版服务打开时自动迁移。建表、数据转换、原始快照备份和版本登记一起提交，失败会回滚。原始工作区保存在 `migration_backups` 的 `normalized-project-storage-v1` 记录；旧表保留为 `workspace_legacy_v0`，原名 `workspace` 改为只读视图，防止旧版程序继续写入已过时的数据。此视图展示的是迁移前记录，不代表当前工作区，也不提供自动降级。升级前仍应停止服务并备份整个数据目录。

界面轮询使用精简状态接口，只传当前项目、本集最近消息和全部项目的导航摘要；素材、资产和更早聊天通过项目分页接口读取。剧集档案和工作记录按需请求完整历史。原有不带参数的 `GET /api/state` 继续返回完整工作区，模型密钥仍不进入响应。接口字段、分页规则和存储表见[架构说明](architecture.md#项目快照与分页接口)。

这些优化减少数据库写入量与日常网络传输量。服务启动时仍会将整个工作区恢复到内存，保存时仍扫描和比较全部实体；当前并非按需加载项目的存储层，也未引入多实例并发写入或远程数据库。

### Webhook 契约

```json
{
  "kind": "video",
  "model": "your-model",
  "prompt": "当前节点任务和本项目上下文",
  "system": "Agent 系统指令",
  "references": [
    {
      "id": "asset-id",
      "name": "主角",
      "type": "character",
      "description": "已确认的角色设定",
      "content": "详细标准",
      "url": "https://your-service.example/reference.png",
      "locked": true,
      "version": 1
    }
  ]
}
```

配置密钥时请求携带 `Authorization: Bearer ...`。

同步文字响应：`{"text":"创作结果"}`。

同步图片 / 视频响应：`{"url":"https://.../media.mp4","text":"素材说明"}`。媒体 URL 需要为 HTTP(S)。

异步响应：

```json
{
  "status": "queued",
  "jobId": "job-123",
  "statusUrl": "https://your-service.example/jobs/job-123"
}
```

工作台会 GET 同源 `statusUrl`，完成响应 `{"status":"completed","url":"https://.../media.mp4"}` 或 `{"status":"completed","text":"结果"}`；失败响应 `{"status":"failed","error":"原因"}`。默认每 2 秒轮询，最多 120 次；文字 / 图片总超时 180 秒，视频 300 秒。健康检查 GET 配置地址返回 `{"ok":true}` 或 `{"status":"ok"}`。

停止操作取消本地等待，无法代替供应商侧的取消任务 API。远端任务可能仍继续运行；重试前可根据错误记录中的任务 ID 检查供应商状态。程序不会自动重新提交生成 POST。

OpenAI 兼容部分依据官方 [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 与 [Images](https://developers.openai.com/api/reference/resources/images/methods/generate) 接口约定实现。

## 记忆策略与当前边界

这是可运行的首版工作台，不是已完成全部专业后期功能的剪辑器：

- 项目摘要聚合制作状态、固定事实、资产标准和决策；模型上下文只带有限的近期对话和原著节选，避免无限追加历史。
- 原著总计可保存 200 万字，最多 100 章；单次导入最多 20 万字。大篇幅原文当前使用有上限的首尾节选，省略区域明确标记。尚未实现向量检索、逐章完整语义索引，因此长篇改编应分批提供章节并固定关键事实，不能保证自动理解整本小说。
- 总制片使用可审计的节点状态机调度预设专业 Agent，尚未实现任意拓扑的自主任务规划或第三方 Agent 协议。
- 当前实际视频路径只生成已批准分镜中的首个非后期镜头素材；后续多镜头批量生产、配音、字幕时间轴、音乐与最终成片合成仍需要扩展。交付节点依据媒体台账生成制作清单与剪辑计划，不自动渲染成片。
- JSON 导出只包含素材索引，不内嵌媒体二进制；本地已保存文件需要随数据目录一起备份，未成功补存的供应商临时 URL 仍可能过期。
- 内容校对是创作辅助节点，不能代替版权授权核实或平台最终审核。
