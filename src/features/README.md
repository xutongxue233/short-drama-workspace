# 功能模块

| 目录        | 职责                                             | 对外入口   |
| ----------- | ------------------------------------------------ | ---------- |
| `projects`  | 项目标题与本集范围、创建项目、原著导入、邀请成员 | `index.ts` |
| `workspace` | 组合项目标签页；聊天记录、输入器与待确认内容     | `index.ts` |
| `workflow`  | 制作流程、制作概览、节点成果和重跑确认           | `index.ts` |
| `assets`    | 全局资产库、筛选、媒体展示和资产编辑             | `index.ts` |
| `memory`    | 摘要、固定事实、创作决策                         | `index.ts` |
| `agents`    | Agent 配置及模型绑定                             | `index.ts` |
| `models`    | 接入预设、服务配置、连接测试                     | `index.ts` |

模块内部使用直接相对路径；跨模块通过 `index.ts` 公开入口引用。`workspace/ProjectWorkspace.tsx` 组合其他项目功能；这些子功能不能反向依赖 `workspace`，避免循环依赖。

聊天按行为拆分：`ChatPanel` 管理滚动跟随，`ChatHistory` 展示记录与节点成果，`ChatComposer` 维护项目草稿、@选择和发送状态，`ApprovalCard` 管理反馈及确认。切换项目时通过项目 `key` 重建聊天局部状态，草稿仍按项目保存。

`shared/mentions.ts` 负责纯文本提及识别；输入器只向它传入已入群且启用的成员。正文的首个有效 `@名称` 决定回复对象，未指定时交给总制片。候选选择、输入高亮和请求目标必须保持一致，删除提及后不能保留隐藏的回复对象。聊天记录也对已知名称和 `@你` 高亮，渲染为文本，禁止拼接 HTML。

聊天等待状态同时使用输入器的即时反馈和 `/state` 返回的 `project.chatPending`，因此切换标签页后仍能恢复正在回复的成员。聊天生成与制作节点的 `running` 是两个独立状态。模型失败使用带 Agent 身份的 `error` 消息；缺少模型配置时显示具体缺口，不返回模板回执。

输入器提供自动协作与仅讨论两种消息模式；明确的总制片创作指令由后端调度工作流。`WorkflowStatusCard` 为尚未启动、暂停或失败的项目显示下一位成员与继续入口，审批期间不再提供启动按钮。审批卡按后端 `fields` 展示制作方案，批准携带答案和补充要求，返修仅提交反馈。新审批到达时定位到卡片标题，避免较高的表单只显示底部按钮。

组件内保留表单编辑状态。服务端写入由传入的 `Action` 或保存回调执行；不要把全应用状态复制到单个功能。UI 通用控件来自 `src/ui`；跨业务的展示组件在 `src/components`。

原有工作台样式按模块放在各自 `styles/` 目录，统一通过 `src/styles.css` 的有序导入装配；调整响应式布局请同时检查 `src/styles/responsive/`。Agent 与模型中心的样式由对应模块入口加载。
